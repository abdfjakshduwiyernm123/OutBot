# OutBot's Coding Standards

- Use tabs instead of spaces
- Use consistent and descriptive names for your variables, functions, parameters, classes, and files/directories
- Use DRY where appropriate
- Use Google style docstrings for all your functions and methods. 
- Use normal docstrings for classes and make sure docstrings are under 100 characters
- Try not to use emojis
- Try to write **SIMPLE** code, rather than **CLEVER** code
- Avoid nesting where possible
- You may use Ai but make sure you proofread all the code Ai gives you
- Before submitting your code, please run your code through ruff, codespell, pyright, and tests
- Please read and listen to comments
- Please make sure to write tests for any new commands you implement or update old tests to keep them relevant
- Update documentation or other commands if the code you added causes them to be out of date
- DO NOT ADD FEATURES THAT COLLECT USER DATA UNNECESSARILY
- Only collect/use what is needed

# How To Contribute

There are two ways to contribute to OutBot:  
1) Submit a [Pull Requests](#1-pull-requests)   
2) Become a [Developer](#2-becoming-a-developer-at-outmyth)  

## 1) Pull Requests

1) Fork/clone the repository
2) Create a branch for your changes
3) Make your changes while following OutBot's coding standards 
4) Add or update tests or documentation where appropriate
5) Run through ruff, codespell, pyright, and tests
6) Proofread your changes
7) Open a pull request explaining:  
    - What did you change?  
    - Why you changed what you changed?  
    - What benefits OutBot will gain?  
    - Will this help users have a better experience with OutBot?  
    - Ai use  
    - How you would like to be credited  

Your code should follow [OutBot's Coding Standards](#outbots-coding-standards).

## 2) Becoming a developer at OutMyth

1) Fork the Repository and add your changes.
2) Open a ticket on [OutMyth's Discord Server](https://discord.gg/Sc5vAvTJtc) requesting to become a developer.
3) You will be told if you are accepted via the ticket you opened.
4) Submit your changes via a pull request with how you would like to be credited.
5) If you are accepted you still have to follow what everyone else does the only difference being you will have access to more commands and more of  
OutBot's codebase
6) You **CAN** still present your changes even if you're rejected.

Please keep in mind being a developer does not exempt you from OutBot's coding standards. Being a developer is like being a moderator for OutBot.
